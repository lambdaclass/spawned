# Spawned v0.6.1 — draft

Proposed patch release for the dedicated async runtime's worker budget.
Version 0.6.0 is already published. This note does not indicate that 0.6.1 has
been tagged or published, or that Ethlambda's production latency cause is known.

## Dedicated async actors

`tasks::Backend::Thread` continues to run an actor on a dedicated native root
thread. Its private Tokio runtime now has **one async helper worker**, instead
of inheriting Tokio's machine-sized/environment-configured worker count per
actor. The same bound applies to `spawned_rt::threads::block_on`.

The runtime remains multithreaded to preserve independent async helper progress
while the root blocks, `block_in_place`, timers and async I/O. Actor/protocol
signatures and startup calls are unchanged. Blocking helpers, DNS and filesystem
operations can create further threads, so this is not a two-total-threads
guarantee. CPU-heavy helpers must cooperate or use blocking workers; their
parallelism budget has changed.

`TOKIO_WORKER_THREADS` no longer changes this dedicated bridge's helper count.
Applications that intentionally relied on a larger private helper pool should
validate their workload before upgrading. The ordinary shared async backend is
unchanged. The synchronous `threads` actor module still uses blocking mailboxes;
this patch does not create a Tokio-free build.

## Validation and interpretation

The [runtime review](../reviews/dedicated-runtime.md) links focused helper, timer,
TCP, blocking, shutdown and worker-bound regressions, including a negative
control against the old implementation. Existing workspace/default/all-feature
and Clippy checks passed; [CI for the runtime fix](https://github.com/lambdaclass/spawned/actions/runs/42327661977)
also passed.

The [Engine client / actor research](../../research/client-observations/2026-11-06-ethlambda-ab/server-probe/README.md)
separates framework versions, metrics and local scheduling from controlled
loopback RPC responses. It does not reproduce a full beacon workload or prove
the cause of the production eth4/eth5 difference. The one-worker and concurrent
follow-up evidence must be evaluated alongside the same-node canary before
publishing this patch under the current rollout plan.

The [worker-budget follow-ups](../../research/client-observations/2026-11-06-ethlambda-ab/server-probe/one-worker/README.md)
passed 180 local functional/resource-gated runs, including 4/16 in-flight RPCs
and longer idle-gap comparisons. Loaded request tails improved in those tests;
rare idle outliers remained. These are workload-specific observations, not a
promise that every application or percentile improves.

Release preparation still requires the final version/lockfile bump, checks on
that exact commit, publication and registry verification. No production node or
Ethlambda dependency is changed by adding this draft.
